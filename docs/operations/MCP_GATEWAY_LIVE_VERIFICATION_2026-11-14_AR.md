## 4) توزيع التعليمات حسب مكان تطبيقها
- GitHub: `AGENTS.md` هو المرجع التنفيذي للوكيل الذي يقرأ المستودع؛ يجب أن يقرأه كل workflow/agent قبل التعديل.
- Lovable: Project Knowledge وWorkspace Knowledge يحملان التعليمات للوكيل داخل Lovable؛ يجب المحافظة على النص الموجود وإضافة قواعد SiteDocs دون استبداله.
- Cloudflare: إعداد Worker وسرّه لا يحملان تلقائياً تعليمات التطوير. التعليمات يجب أن تكون ضمن مستندات GitHub التي يقرأها وكيل Cloudflare أو ضمن سياسة Gateway بعد بنائها.
- Supabase: لا توجد في الاتصال الحالي قناة تعليمات عامة مؤكدة للمشروع؛ لا ندعي وصول المذكرات إليه. يجب تطبيق السياسات عبر SQL/RLS والسياسات الموثقة بعد استعادة الصلاحية، دون تعديل قاعدة البيانات الآن.
- ChatGPT: تُستخدم قرارات المشروع وسجل التنفيذ في سياق الوكيل؛ لا يعني ذلك أن كل أداة خارجية استلمت التعليمات تلقائياً.
- Gateway: حالياً لا يملك موصلات هذه الأنظمة؛ لا يمكنه تعميم التعليمات أو تنفيذ مهامها قبل تطوير الربط والتحقق منه.
