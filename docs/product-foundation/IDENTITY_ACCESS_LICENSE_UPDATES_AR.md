# SiteDocs — الهوية والوصول والتراخيص والتحديثات

> مواصفة تأسيسية؛ لا يوجد في هذه الوثيقة ادعاء بأن المصادقة أو الترخيص أو التحديثات المركزية قد نُفذت.

## 1. تجربة الدخول

- صفحة دخول تحمل هوية SiteDocs الذهبية الداكنة، وتدعم العربية والإنجليزية.
- البريد الإلكتروني أو معرف المستخدم وكلمة المرور.
- إظهار/إخفاء كلمة المرور، استعادة الحساب، ورسائل خطأ لا تكشف وجود الحساب.
- مصادقة متعددة العوامل (MFA) للحسابات الحساسة، مع فرضها على مالكي النظام ومديري الشركات وفق سياسة المؤسسة.
- جلسات آمنة، انتهاء صلاحية، إبطال الجلسات، وإدارة الأجهزة الموثوقة.
- لا تُخزن كلمات المرور كنص صريح؛ يعتمد التحقق على مزود هوية موثوق وتجزئة كلمات مرور قوية لديه.
- لا تُخزن مفاتيح الخدمة أو أسرار التوقيع في المتصفح أو المستودع.

## 2. نموذج الهوية والصلاحيات

تسلسل النطاق:
System → Tenant/Company → Project → Module/Record.

الأدوار الابتدائية المقترحة:
- System Owner: إدارة المنتج والتراخيص والإصدارات.
- System Admin: إعدادات النظام العامة ضمن التفويض.
- Company Owner/Admin: إدارة شركته ومستخدميها.
- Project Manager: الإشراف على مشروعه وفق الصلاحيات.
- Document Controller: إنشاء وإدارة المستندات والإصدارات المسموح بها.
- Reviewer/Engineer: المراجعة والرد ضمن التخصص والمرحلة.
- Finance Manager/Accountant: العمليات المالية والمحاسبية حسب فصل الواجبات.
- Employee/Viewer: نطاق محدود للقراءة أو إدخال ما كُلف به.

تُنفذ الصلاحيات كقدرات دقيقة (permissions) لا كإخفاء عناصر الواجهة فقط. كل عملية حساسة تتحقق على الخادم وفي سياسات قاعدة البيانات. صلاحيات العرض، الإنشاء، التعديل، المراجعة، الاعتماد، الترحيل، الصرف، التصدير وإدارة المستخدمين مستقلة.

## 3. نموذج التوزيع التجاري

يُدار المنتج من مصدر موحد، مع قنوات إصدار منفصلة:
- Core Source: المصدر الأساسي والاختبارات والتوثيق.
- Commercial Release: إصدار معتمد للعملاء.
- Internal Maintenance: بيئة داخلية للتطوير والإصلاح والتحقق.

أنماط البيع:
- Cloud Subscription: خدمة سحابية متعددة العملاء.
- Enterprise License: تثبيت خاص لدى العميل أو في بيئته السحابية.
- Source License: ترخيص كود مصدر بعقد مستقل يحدد حق الاستخدام والتعديل والتوزيع والدعم. بيع ترخيص المصدر لا يعني تلقائياً نقل ملكية الملكية الفكرية.

لا تُنشأ فروع كود دائمة مستقلة لكل عميل إلا عند وجود سبب تعاقدي وتقني واضح. الأفضل إعدادات وميزات اختيارية وواجهات تكامل مع خط إصدار موحد.

## 4. سجل الترخيص

حقول مرجعية مقترحة:
- license_id وtenant_id.
- edition وdeployment_mode.
- status: trial, active, grace_period, suspended, expired, revoked.
- valid_from وvalid_until.
- purchased_modules وseat_limit وproject_limit حسب العقد.
- update_entitlement_until وsupport_entitlement_until.
- license_key_fingerprint (لا تخزن المفتاح الخام إن لم تكن هناك ضرورة).
- issued_at وlast_verified_at وaudit metadata.

يجب تعريف سياسة العمل عند تعذر الاتصال بخدمة الترخيص (offline grace) دون إيقاف وصول العميل إلى بياناته. انتهاء الترخيص لا يبرر حذف البيانات أو حجب تصديرها.

## 5. مركز الإصدارات والتحديث

بيانات الإصدار:
- version وrelease_channel (stable/beta/enterprise).
- release_notes وartifact_digest.
- signature وminimum_supported_version.
- required_migrations وcompatibility metadata.
- released_at وrollback_compatibility.

مسار النشر:
1. بناء artifact من commit محدد وموسوم.
2. تشغيل lint وtypecheck والاختبارات وفحص الاعتماديات.
3. توقيع artifact والتحقق من digest.
4. نشره إلى قناة اختبار.
5. اختبارات ترقية على نسخة قاعدة بيانات معزولة ونسخة احتياطية قابلة للاستعادة.
6. إتاحة الإصدار للترخيص والقناة المناسبين.
7. تثبيت تدريجي مع health checks وسجل نتيجة.
8. عند الفشل، إيقاف التوسع واستعادة التطبيق؛ أما migrations فيجب تصميمها بتوافق رجعي أو بخطة forward-fix، لأن rollback آلياً قد لا يكون آمناً.

لا تُشغّل migrations تلقائياً على بيانات العملاء دون تحقق ونسخ احتياطي وموافقة/سياسة تشغيل موثقة.

## 6. أمن سلسلة التوريد

- فصل صلاحيات الوصول إلى المستودع ومفاتيح التوقيع وبيئة الإصدار.
- عدم تضمين أسرار الإنتاج في build العميل.
- استخدام least privilege وMFA وسجل تدقيق إداري.
- تحديثات موقعة والتحقق من المصدر والتجزئة.
- SBOM وفحص الثغرات والاعتماديات.
- حماية endpoints الخاصة بالترخيص والتحديث من إعادة التشغيل والتلاعب.
- لا يعتمد التطبيق على واجهة العميل وحدها لتحديد حالة الترخيص أو صلاحيات المستخدم.

## 7. قرارات لم تُحسم بعد

- هل الإصدار الأول Cloud فقط أم Cloud وEnterprise معاً؟
- هل ترخيص المصدر منتج فعلي في أول إصدار أم اتفاق خاص لاحق؟
- سياسة عدد المستخدمين والمشاريع والوحدات لكل باقة.
- سياسة الاتصال غير المتصل وفترة السماح.
- مزود الهوية النهائي ومزود الفوترة.
- نموذج دعم وصيانة العملاء واتفاقيات مستوى الخدمة.
